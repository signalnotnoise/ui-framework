# Version 1.0.0 — end-to-end release record

Status: candidate preparation, November 15, 2026. Public release is conditional
on exact-commit validation, performance and publication success. Alpha.7 remains
the latest verified public package until this record confirms otherwise.

## 1. Establish the scope and preserve the baseline

The repository history begins with the September 17 experimental source release
(`5500dbb`). September 18 work added virtualized focus restoration, responsive
layout/scoped styling, retained navigation, bound editors and pickers. The first
NuGet preview and GitHub Trusted Publishing were prepared in `78c88fb`, followed
by explicit public-installation verification. That source revision remains the
accepted performance comparison baseline.

September 18–24 work added accessibility labels, repeated performance evidence,
retained native WPF islands and themed native button content. Rendering recovery,
notification delivery and row lifecycle were hardened before retained workspace
layouts were added. Editor timeouts blocked publication rather than being waived;
layout-editor checks became part of CI and publishing in `ac7bd58`.

October work corrected native style isolation, compact input/button sizing and
package-consumer behavior through alpha.4/alpha.5. FW-016 documented the public
API and compatibility checks. FW-003 identified WPF presentation startup as a
bottleneck and tested initialization order (`be6e1d1`). Alpha.6 added contrast
theme support, virtual-row automation coverage and reduced mount allocations.
The user confirmed physical IME/contrast checks on October 29.

FW-007 then improved keyed shuffles/reversals and mount allocations (`5fd4a2a`).
FW-022 measured editor mount phases; `f7c7320` established source-first editor
benchmark initialization and the exact-commit hosted performance gate. These
benchmark setup changes are recorded separately from framework runtime changes.
Native/WebView2 ownership and sustained memory work followed, culminating in
alpha.7 on November 13 and the final acceptance work described below. This
chronology is grounded in Git history; dated records retain the exact test scope.

The release consolidates the framework acceptance campaign, rather than adding
another control catalog. The supported contract covers declarative C# descriptions,
reactive state/bindings, retained components, WPF rendering, keyed virtualization,
navigation, layout, themes and application-owned native islands. Windows 11 x64
with .NET 10 is the tested adoption matrix. [The API contract](../api-contract.md)
defines identity, threading, composition, error recovery and ownership guarantees.
Direct View construction remains supported; computed reads remain uncached.

The accepted performance baseline remains
`78c88fb901c202e3c2e49b6de300d1ce2369e00b`; its budgets are unchanged. Local
comparisons against alpha.7 provide additional evidence but do not replace the
exact-candidate hosted release gate.

## 2. Complete ownership and acceptance work

- FW-010 established scoped native/WebView2 initialization, close-race, focus,
  failure/recovery and resource-lifetime acceptance. Provider timeout/recovery
  remains application-owned; this is not a universal browser-provider guarantee.
- FW-018 separated measurement-tool retention from framework retention, bounded
  reporting, compared focus/native resources with plain WPF and traced cached
  automation children retaining detached editors. Weak peer registration and
  cache invalidation release those editors without allocating for every row.
  Directly retained editor peers still explicitly own their editor.
- Scoped memory budgets passed 12 long runs. Workload-specific evidence and
  historical failures remain preserved; these budgets do not prove every app leak-free.
- FW-017 completed light/dark, narrow/wide and application-owned error appearance
  acceptance. FW-019 added a standalone NuGet-only workspace, clean restores,
  source/binary upgrade checks and explicit startup/shutdown ownership.
- FW-012 reconciled alpha.7 publication records with actual hosted artifacts and
  public package hashes. FW-027 packaged current code separately as alpha.8-local.1.

These changes and raw evidence were committed in `a1d2ed6`. Upstream alpha.7
publication records and the pinned artifact-download action were merged in
`e1aad81`. The previous upstream Validate failure was a stale generated graph;
the graph was regenerated instead of treating that failure as a performance issue.

## 3. Validate the accumulated implementation locally

[FW-027](../fw027-local-candidate-2026-11-15.md) records 176 passing framework
tests, 15 visual checks, 21 stress assertions, real-window/native shutdown,
package smoke, public API guards and 25 graph-tool fixtures. Seven alternating
baseline/candidate pairs against alpha.7 passed all 32 source comparison metrics.
Mount/update timing medians were 0.02–2.30% lower, with effectively unchanged
allocations and identical component work.

The smaller independent package workspace passed 14 source/binary upgrade runs
and collected all 168 host/editor probes. It also recorded a 7.40% full-list mount
increase and 4.01% virtual update increase; raw ranges overlap, but their cause
is not proven. They are retained as diagnostic observations, not hidden or
represented as a universal speedup. Prior 12-run memory evidence is reused only
after confirming the framework sources match; it is not a newly repeated soak.

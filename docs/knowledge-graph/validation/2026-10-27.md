# Visual Git correlation validation — October 27, 2026

FW-021 adds a bounded offline Git export and viewer controls. Existing curated
schema v1, canonical graph schema v2, protected hook, vendor/license and query
commands are preserved. No framework runtime, package, application or performance
baseline changes are part of this item; FW-005/006 work remains separate.

## Automated evidence

`python scripts/test-knowledge-graph.py` passes 25 tests locally, including Node.js
model and viewer-handler tests. The original index/worktree isolation, protected
outputs, hook staging, stale renderer/vendor detection, canonical embedded-data
equivalence, bounded queries, cache reconstruction, rename and deleted-impact
checks remain passing.

New fixtures verify:

- Root commits compare with an explicit empty tree; first-parent merges compare
  with the correct parent. Shallow boundary parents are marked unavailable and
  do not produce fabricated additions or a failing missing-object query.
- Renames with spaces, deletions, commit subjects containing HTML/script-like
  text, template-like filenames remaining inert data, bounded history and
  deterministic standalone export.
- Uncommitted files appear only in the worktree initial view, not historical
  frames; exports do not stage files and refuse tracked or nonignored repo
  output paths. Existing artifacts require explicit `--force`.
- Changed content and executable modes are detected through Git identity even when graph relationships
  are unchanged. Removed nodes/relationships stay in the comparison view, and
  repeated references between a source/target pair remain distinct.
- The actual exported scripts run with embedded Three.js in a small DOM fixture
  without WebGL. Tests select a deleted file, inspect its history, choose a
  commit, compare identical revisions, restore the initial graph, verify stable
  positions across revisions, and reject
  malformed imports. This verifies handlers and fallback behavior, not pixels.

The initial shallow-clone test exposed a missing-parent query. It was fixed by
reading real commit parents and explicitly recording unavailable first-parent
changes, then the focused and full suites passed.

## Limits and remaining verification

The browser tool rejects local `file://` URLs. Visual browser inspection is
unperformed; no alternate protocol, server or browser workaround was attempted.
The local export is intended to be opened by the user in their browser.

Exports cover eight recent first-parent commits by default, at most 20, plus
parent snapshots. These are not all-branch history or live Git queries. Rename
following is heuristic. Graphs are reconstructed with the current extractor;
C# calls and using directives remain unresolved. Relationship differences show
syntax/evidence or curated claims, not semantic/runtime impact. No network fetch,
framework benchmark, commit, push or publication is performed by the exporter.

# FW-040 button tooltip implementation and validation

November 21, 2026. Unreleased work based on runtime revision `09cd20b`.
The user selected Button/IconButton first. Prior staged FW-041 work is preserved.

`View.Tooltip(string?)` and `TooltipText` are additive unshipped core API.
Nonempty text overrides the hint; null restores automatic behavior; empty text
suppresses hints including those supplied by styles. Accessible names remain
independent. The original icon-only accessible-name fallback is preserved.
See the [contract](tooltips.md) for supported kinds and ownership rules.

A small WPF `ButtonTooltip` helper owns native property precedence, separated
from `IconButtonContent` visual composition. No native tooltip object enters
core; no timer, cache, subscription or new policy constant is added. Default
plain buttons skip the tooltip patch helper. Each new C# file declares one type.

Final validation: 229/229 framework tests passed, including seven new tooltip
checks. A real offscreen window verifies native focus traversal and retention of
keyboard focus during hint updates. This uses programmatic traversal, not physical
Tab input. Earlier
test-only setup failures (visual-tree inspection before layout) are preserved
alongside the successful rerun. API compatibility builds and both negative guard
probes passed. Local `1.2.1-tooltips-local.1` packages passed isolated installation,
new tooltip initial/update assertions and the existing package smoke checks.
This local version is not a NuGet.org publication.

Performance comparison against pre-change runtime `09cd20b` passed 32/32 checks:
seven alternating sample pairs, same harness/SDK/machine, full-list, virtualized,
themed full-list and layout-editors. Accepted release baseline and budgets remain
unchanged. This pre-change comparison is diagnostic, not hosted release evidence.

Median changes (candidate versus baseline):
- Full-list: mount +2.59%, update +2.84%; allocations +0.16% / +0.38%.
- Virtualized: mount +1.68%, update +2.37%; allocations +0.29% / +1.03%.
- Themed full-list: mount +0.42%, update +3.04%; allocations +0.13% / +0.40%.
- Layout editors: mount -3.83%, update +0.08%; allocations +0.01% / +0.08%.

Component builds, mounts and unmounts are unchanged in every scenario. The new
reference field has a small cost even on descriptions without hints. The helper
fast path avoids native tooltip work for ordinary buttons; no allocation cache
or unrelated representation change was introduced to chase small timing shifts.
These workloads check general renderer impact, not tooltip-heavy popup throughput.
Passing budgets is not a claim of zero overhead or statistically proven speedup.

The [evidence manifest](verification-evidence/2026-11-21-tooltips/manifest.json)
identifies the archived raw pairs, source/binary manifests, candidate sources,
failed and passing test results, API/package logs and local package hashes.
SDK 10.0.402 and runtime 10.0.13 were used for both comparison sides. No budgets
or accepted baseline were changed. Three skill-reference fixtures, reference
freshness and documentation checks also passed.

Acceptance limits: native policy and automation-name assertions do not establish
physical screen-reader or visible-popup acceptance. WPF continues to own popup
presentation and lifetime; application styles own keyboard/disabled policy
overrides. This change does not add a tooltip-specific theme or shortcut binding.
The shipped skill API inventory remains accurate for 1.2.0; source guidance
explicitly labels the additions unshipped.
